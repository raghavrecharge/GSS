# Browser reconnaissance

## Preconditions
- Confirm the URL and the user's authorization scope.
- Use an available browser automation tool or a user-operated browser session. Do not assume a browser tool exists.
- If the site requires login, use only an account the user is authorized to use. Never ask the user to paste passwords or tokens into source files or reports.

## Procedure
1. Open the supplied URL and record final URL, title, date, browser, viewport, and access result.
2. Map the visible information architecture: navigation groups, route links, footer links, tabs, and in-app navigation.
3. Visit each in-scope route. Record route, page purpose, primary action, secondary actions, shared shell, and unique components.
4. Exercise visible controls using ordinary UI interactions:
   - navigation, tabs, dropdowns, search, filters, sort, pagination;
   - forms and validation;
   - dialogs, drawers, menus, tooltips;
   - upload controls only with harmless synthetic files;
   - success, failure, empty, disabled, loading, focus, and hover states where safe.
5. Map critical workflows as numbered steps with preconditions and expected outcomes.
6. Repeat key pages at desktop, tablet, and mobile widths when feasible.
7. Capture screenshots with consistent viewport dimensions and state labels.
8. Record only network requests generated by normal authorized interactions when network inspection is available. Do not fuzz, enumerate, or probe endpoints.
9. Update the evidence ledger and page inventory. Mark inaccessible routes as blocked/unknown, not as nonexistent.

## Evidence record format
For each page:
- Page ID and route
- Purpose
- Shared shell and components
- Primary and secondary actions
- Visible states
- Responsive changes
- Screenshot/evidence IDs
- Observed facts
- Inferences and confidence
- Unknowns/blockers

## Stop conditions
Stop and report when:
- login or access is unavailable;
- a challenge, CAPTCHA, paywall, rate limit, or access control blocks progress;
- the next action would expose private data or change real production state;
- an action could send messages, charge money, delete records, invite users, or otherwise affect real users.

Ask for a safe test environment or explicit confirmation before consequential actions. Never bypass a control.

## Output
Produce `product-map.md`, `page-inventory.csv`, `user-flows.md`, and evidence-ledger updates. Include coverage counts: routes found, routes inspected, workflows mapped, states observed, and blocked items.
